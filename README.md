# 🧪 In-Pocket Analysis Toolkit

**Quantum-based interaction and structure analysis of ligand environments in proteins**

---

## Overview

This toolkit provides two main Python scripts for structure-based analysis of protein-ligand systems:

- **In-Pocket Analysis**: Focuses on analysing local interactions between a central residue (e.g., ligand, metal ion) and nearby residues.
- **Fragment Analysis**: Allows optimization of a custom-defined pocket/substructure, enabling studying environment-dependent effects and covalent interactions.

Both scripts are built on [ULYSSES](https://gitlab.com/siriius/ulysses) for QM-based refinement using custom C++ executables for protonation and geometry optimisation. They also require external tools like RDKit, Open Babel, Gemmi, and mrcfile.

---

## Features

- Ligand-protein interaction energy calculation.
- Structural refinement using GFN2-xTB. Other semi-empirical QM methods available through [ULYSSES](https://gitlab.com/siriius/ulysses).
- Automated protonation (RDKit, CCD, VSEPR, or Open Babel).
- Support for PDB and CIF formats.
- Water and residue-flipping options for critical residues.
- Acid-base and tautomerism available through RDKit.
- Fragment mode for analysing covalently bound or extended systems.
- Output includes refined structures, interaction energies, and statistics.

## Installation

### Dependencies

- [ULYSSES](https://gitlab.com/siriius/ulysses) (included in `src/`, so no extra effort needed)
- Python 3
- RDKit
- Open Babel (optional)
- g++ (tested with GCC and Clang)

### Install Python environment:

To install the python environment required for running calculations do the following
```bash
conda create -c conda-forge -n ipa-env rdkit
conda install conda-forge::gemmi #or `pip install gemmi`
conda install conda-forge::mrcfile #or `pip install mrcfile`
```

Calculations can be performed by activating the environment beforehand
```bash
conda activate ipa-env
```

### Install Python environment with [uv](https://docs.astral.sh/uv/):

```bash
uv sync
```

To activate this environment, add `uv run` to the beginning of all commands, e.g.

```bash
uv run python in_pocket.py [ARGS]
```

### Compilation

Compile the required C++ programs using the script `install.py` by running
```bash
python install.py
```

Alternatively, compile everything manually using
```bash
g++ gfn2xtb_in_pocket_opt.cpp -O3 -o gfn2xtb_in_pocket_opt.exe
```

## Usage

### Workflow

In-Pocket is a tool for the analysis of protein–ligand complexes. It can be used to optimize the chemical interface between ligands and their biological environment, or to identify the most representative structural model within a given Hamiltonian. At present, the code relies on external tools for protonation handling, including the assignment of protonation states and tautomeric forms. Because these tools are not fully robust in all situations, In-Pocket provides several alternative protocols to ensure that an analysis can still be carried out.

The default workflow uses RDKit-based protonation. We recommend enabling the tautomers option. Dimorphite, which is used to generate protonation and tautomeric states (hereafter referred to as chemical states), may occasionally produce chemically less relevant species, such as imidic acid tautomers of amides or even protonated amide groups. For this reason, we recommend pre-selecting only chemically meaningful states through the interactive prompt.

RDKit protonation may fail in some cases, for example when ligand geometries are highly distorted. If the ligand is described by a Chemical Component Dictionary (CCD) entry, this file can be supplied as an argument to follow a CCD-based protonation route. In other cases, such as ligands generated by docking software, the structure may only be available as an SDF file. In-Pocket therefore also supports calculations from a user-supplied SDF file, which is generally a robust alternative. As a last resort, protonation can be performed with Open Babel. In our experience, however, Open Babel may also produce problematic protonation states, particularly for strongly distorted ligand structures. In such cases, it may be useful to intentionally provide an incorrect ligand charge, allowing the user to manually correct the protonation state generated by Open Babel. The program may be resumed by inputing the correct charge. Even so, caution is advised when using this option, as the protonation states of some residues, most notably arginine, may be assigned incorrectly. By contrast, RDKit protonation may introduce small deviations in ligand geometry. To address this issue, we also provide a prototype workflow based on our own VSEPR protonation scheme, although this feature is experimental and no guarantee of reliability can be given.

After completing the standard In-Pocket analysis, the user may choose to run a full pocket analysis using Fragment Mode. Alternatively, Fragment Mode can be run directly in order to analyze many-body effects, such as water-mediated interactions, or covalent linkages between ligand and protein. Transition metals are included in this latter category.

Running Fragment Mode requires the definition of a protein pocket environment. This can be specified manually. Alternatively, the output of a previous In-Pocket analysis can be used to reconstruct the pocket automatically. For consistency, only a single chemical state should be selected for the surrounding residues.

The examples below are taken directly from our test set. Additional examples can be found in the text files located in the tests/ directory.

### 🔍 In-Pocket Analysis

Analyse interactions around a central residue:

```bash
python in_pocket.py --pdb tests/4WA9.cif --active-residue 9000 --chain B --output tests/axitinib_analysis --distance 3.6 --alpha 1.0 --kappa 0.025 --use-ip-structure --verbose
```
This program call runs In-Pocket analysis on the 4wa9.cif file, focusing around the residue 9000 of chain B. The output is stored into the folder tests/axitinib_analysis/. The analysis is run on a neighbourhood of 3.6 A around the central residue.
The In-Pocket bias potential is defined using $\alpha = 1$ and $\kappa = 0.025$, though this is not required as input (those are the default values). The In-Pocket refined structure is also used for all calculations (option `--use-ip-structure`).
To use Open Babel protonation you need to overwrite the RDKit default:

```bash
python in_pocket.py --pdb tests/4WA9.cif --active-residue 9000 --chain B --output tests/axitinib_analysis6 --distance 3.6 --alpha 1.0 --kappa 0.025 --use-ip-structure --verbose --protonation obabel
```
Note that tautomer analysis is only available with RDKit. This requires turning on tautomerisation.

```bash
python in_pocket.py --pdb tests/4WA9.cif --active-residue 9000 --chain B --output tests/axitinib_analysis3 --distance 3.6 --alpha 1.0 --kappa 0.025 --use-ip-structure --verbose --tautomerise
```

Alternatively, if a CCD file is available, you can use it to set the ligand's protonation state.

```bash
python in_pocket.py --pdb tests/4WA9.cif --active-residue 9000 --chain B --output tests/axitinib_analysis7 --distance 3.6 --alpha 1.0 --kappa 0.025 --use-ip-structure --verbose --protonation ccd --ccd-file tests/AXI.cif
```

Note that currently CCD files must be present physically on the machine, i.e., they are not automatically fetched from some repository. The repository currently comes with the CCP4 monomer library integrated (`https://github.com/MonomerLibrary/monomers`), which we keep up-to-date.

In the examples above, we showed In-Pocket using .cif and .pdb files. While both formats work with any protonation scheme chosen, we advise against using the pdb format and RDKit, especially for ligands not in the monomer library. This is because RDKit cannot derive ligand topologies using PDB format, and most likely all ligand's atoms will be classified as sp3.

If you want/need to use RDKit and pdb format, we recommend supplementing the ligand's topology using a reference sdf file. Ligands not in the monomer library will not be modelled properly. 

```bash
python in_pocket.py --pdb tests/4WA9.cif --active-residue 9000 --chain B --output tests/axitinib_analysis2 --distance 3.6 --alpha 1.0 --kappa 0.025 --use-ip-structure --verbose --ligand-topology tests/B9000.sdf
```

No protons are needed in the reference sdf, just the correct assignment of single, double, and triple bonds.

### 🧩 Fragment Analysis

To optimise a user-defined pocket:

```bash
python FragmentAnalysis.py --pdb tests/4WA9.cif --active-residue-a B9000 --active-residue-b B253,B254,B255,B258  --protonation rdkit --tautomerise --output-folder tests/axitinib_fragment_analysis

```

Contrary to In-Pocket Analysis, Fragment Analysis uses obabel by default, not RDKit. RDkit needs to be requested explicitly. Because of RDkit's internal construction, no tautomer searches are included for the protein side (only ATOMs) or for a ligand environment with more than 2 amino acid residues nearby.

Fragment Analysis can also be called from a previous In-Pocket Analysis call. This requires providing an input file as active residue. In this case, we can give the path to the input file as either "active-residue-a", "active-residue-b" or both.
This fetches the ligand defined in the input file and stitches together the IPA-optimised residues from the IPA run, bypassing RDkit or any other protonation algorithm. 
Note that it is sufficient to give the path to the txt/csv file in one of the active-residue cards, and the pocket-sewing mechanism is immediately activated. The arguments passed to the other active-residue are ignored and can take any value.

```bash
python FragmentAnalysis.py --pdb tests/4WA9.cif --active-residue-a tests/axitinib_analysis/list_residues/list_residues.csv --active-residue-b B1 --output-folder tests/axitinib_fragment_analysis3
```

It is also possible to bypass the structural optimisation, providing therefore a fast evaluation of unoptimised pocket complexes. This has the disadvantage that pocket-ligands contacts may be suboptimal. Alternatively, the pocket-ligand complex may simply be fully optimised without any (empirical) restraint.
This is accomplished using

```bash
python FragmentAnalysis.py --pdb tests/4WA9.cif --active-residue-a tests/axitinib_analysis/list_residues/list_residues.csv --active-residue-b B253,B254,B255,B258 --calculation-mode no-opt --output-folder tests/axitinib_fragment_analysis4
```

for no optimisation and

```bash
python FragmentAnalysis.py --pdb tests/4WA9.cif --active-residue-a tests/axitinib_analysis/list_residues/list_residues.csv --active-residue-b B253,B254,B255,B258 --calculation-mode opt --output-folder tests/axitinib_fragment_analysis5
```

for full, unrestricted optimisation. By default, the IPA algorithm is used, meaning the code performs the structural refinement of non-hydrogen atoms biased to the original, experimental structure.

It is also possible to tune the proton optimisation module using the "--ignore-protons" flag (default, protons excluded from bias potential, therefore freely optimised) or "--include-protons" to include protons in the bias potential, therefore only mildly alleviating potential clashes or suboptimal orientations.

#### Options

- `--no-connect-residues`: By default, residues are connected. This means that, if the user defines the pocket residues A1,A58, then the main chain atoms of all residues in between (A2-A57) are considered in the pocket too. This may be turned off using the option `--no-connect-residues`.
- `--no-cap`: Disables capping (discouraged).
- `calcdens=1`: Output electronic density as `.cube` file.
- `solvent`: Implicit solvent model (e.g., water, wet octanol)

## 🐳 Docker Containers

An IPA-Docker-Container is available under `docker pull siriius/ipa:v1`.

To compile a Docker container of IPA, use the following command

```bash
docker build -t ipa .
```

Note that each cpp file compilation inside the container requires approximately 900s and there are 8 cpp files to compile.

If you specifically want a container for a particular architecture, then for Apple M1/M2/M3 Chips, do
```bash
docker build --platform=linux/arm64 -t ipa .
```

For Linux or Intel Mac
```bash
docker build --platform=linux/amd64 -t ipa .
```

For Multi-Architecture platforms use instead
```bash
docker buildx build --platform linux/amd64,linux/arm64 -t ipa:multi -o type=oci,dest=ipa.tar .
```
This will create the file `ipa.tar`, which may be locally used as 
```bash
docker load -i ipa_multi.tar
```

Once loaded, you can use the container with the command

```bash
docker run --rm -it -v "$PWD/4WA9.cif":/data/4WA9.cif -v "$PWD/out":/out ipa conda run -n myenv python /app/in_pocket.py ...
```

An example call is 
```bash
docker run --rm -it -v "$PWD/4WA9.cif":/data/4WA9.cif -v "$PWD/out":/out ipa conda run -n myenv python /app/in_pocket.py --pdb /data/4WA9.cif --active-residue 9000 --chain B --output /out/axitinib_analysis --distance 3.6 --alpha 1.0 --kappa 0.025 --use-ip-structure --verbose
```

This requires having the folder `/out`, so perform a `mkdir out` beforehand. 

## Outputs

For In-Pocket Analysis expect the following output:
- `geometry/`: Optimized and input geometries
- `output/`: QM output files
- `stats.txt`: Summary statistics
- `interaction_energies.csv`: Energies per residue interaction

For Fragment Analysis:
- `geometry/`: Optimized and input geometries
- `output/`: Main output files, namely, summary_file.csv (binding energy, relative energy of the bound state, repulsion energy, other properties), and protein_cut_A_protein_cut_B_ip.csv (QM clash score analysis).

## Limitations

- Only two-body interactions are analysed in In-Pocket (e.g., no water bridges). For more complex environments, use Fragment mode.
- Covalently bound ligands require Fragment mode.
- RDKit may fail with distorted ligands or transition metals
- Open Babel is deprecated and not recommended for future use
